# Tech

## Stack

- Python 3.13 only (`requires-python = ">=3.13,<3.14"`).
- Runtime: Streamlit (App), pandas and numpy (engine), Plotly (charts), XlsxWriter and openpyxl (Excel
  export), platformdirs (Data_Dir).
- Dev: pre-commit, plus the pinned gitleaks binary named in `CONTRIBUTING.md`.
- Docker and Docker Compose for the containerized App (read-only root filesystem, dropped capabilities,
  port bound to `127.0.0.1`, Data_Dir mounted at `/data`).

## Dependencies

- `pyproject.toml` is the only dependency list. There are no `requirements*.txt` files.
- Every dependency is pinned exactly with `==`. Dependabot proposes updates; bump pins in a pull request
  and run `make verify`.
- Prefer the standard library. A new dependency needs a reason in the pull request.

## Commands

```
pip install -e .[dev]        # editable install into .venv
pre-commit install           # pre-commit and pre-push hooks
make run                     # App on the host -> http://localhost:8501
make up / make down          # App in Docker
make verify                  # every check and the smoke test (CI: make verify PYTHON=python)
```

## Checks

- Checks are plain scripts, not a test framework: `scripts/*_check.py` print PASS/FAIL lines and exit
  non-zero on failure. `scripts/verify.py` runs them in name order, then `smoke_test.py`.
- Checks import the installed `retvana` package; never add `sys.path` hacks.
- Hand calculations: a check reads its inputs from `example_plan()` or a small plan built in the check,
  and writes out only the rule. Expected values are derived from the rule, never from the function under
  test. Public constants (tax brackets, OAS amounts, RRIF factors) may be literal.
- Golden master: `scripts/regression_golden.json` is generated by `scripts/make_regression_golden.py`
  and only read by `regression_check.py`. Never regenerate it to make a check pass. Fix the code, or
  change the spec first and then regenerate deliberately.
- Never adjust a check to fit the code. A behaviour change starts with a spec change under
  `.kiro/specs/`.

## Leak guards

- `scripts/forbidden_files.py`, `scripts/check_commit_emails.py` (against `.github/allowed-emails.txt`)
  and gitleaks run in pre-commit and CI. `scripts/release_gate.py` runs them all before a push from a
  maintainer clone and before a release.
- Commit with a GitHub noreply address.
